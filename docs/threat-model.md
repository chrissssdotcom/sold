# Threat model

Method: STRIDE per trust boundary. Single tenant: there is no cross-tenant boundary, so the boundaries that matter are
**internet → storefront**, **internet → staff console/API**, **integrator → public API**, **extension → core**, and **operator → data**.
"Control" names where it lives; "Test" names what would fail if it regressed. Residual risk is stated, not hidden.

## Assets

Customer PII (emails, addresses, order history) · payment state (no card data ever touches us: gateway-hosted fields, ADR/payments.md) ·
staff credentials and sessions · API keys and webhook secrets · inventory/price integrity (revenue) · availability during a sale.

## Boundaries and threats

| #   | Threat                                                                        | Control                                                                                                                                                             | Test                                                                                 | Residual                                                                                                                 |
| --- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 1   | Anonymous caller reaches a staff endpoint (**E**)                             | Every `/api/admin/**` handler is wrapped in `adminRoute` (CSRF → session → `can()`); allowlist of the few session entry points                                      | `route-coverage.test.ts` (source), `security.e2e.ts` (live, every route × 5 methods) | A new route outside the wrapper fails CI; a wrong _permission name_ on a right wrapper does not.                         |
| 2   | CSRF on cookie sessions (**T**)                                               | SameSite cookies (staff Strict, customer Lax) + Origin must match + JSON-only bodies                                                                                | `csrf.test.ts`, admin-api e2e (403 cross-origin)                                     | Same-site sibling subdomains are trusted; do not host untrusted apps on the cookie domain.                               |
| 3   | Session theft/fixation (**S**)                                                | Opaque random token, only its hash stored; HttpOnly; rotation on login; idle + absolute expiry; sign-out revokes server-side                                        | identity integration tests                                                           | Stolen live cookie works until expiry/revocation (no device binding).                                                    |
| 4   | Credential stuffing / brute force (**S**)                                     | scrypt (OWASP parameters), failed-login throttle (`identity/throttle.ts`), uniform error and a dummy hash so unknown users cost the same time                       | identity tests                                                                       | Distributed low-rate attacks: put WAF rules/Turnstile in front (8B).                                                     |
| 5   | Privilege escalation by role editing (**E**)                                  | One `can()` primitive; owner role immutable; role changes audited; extension permissions namespaced `ext:<name>.*`                                                  | rbac tests                                                                           | Owners are all-powerful by design.                                                                                       |
| 6   | Stored XSS via content (**T**)                                                | Blocks validated by Zod schemas, React escaping, no raw-HTML props, email templates escape all values; console CSP uses nonces                                      | block/notify tests, `security.e2e.ts`                                                | Storefront CSP allows inline script (ADR-0005); an extension that renders raw HTML bypasses it.                          |
| 7   | Malicious upload (**T/E**)                                                    | Decode-validate and **re-encode** every image (metadata stripped), SVG refused, 40MP bomb guard, served with `nosniff` + `default-src 'none'`, path traversal tests | `media.test.ts`, `media.e2e.ts`                                                      | libvips/sharp CVEs: kept current (`pnpm audit` clean at Phase 8; two highs fixed by 0.35.5).                             |
| 8   | SSRF via webhook URLs (**I**)                                                 | Connect-time IP check (after DNS), blocks private/link-local/metadata ranges, no redirects followed                                                                 | platform tests                                                                       | Egress firewall (8B) is the second layer and must be configured.                                                         |
| 9   | Forged or replayed webhooks (inbound payments, outbound to merchants) (**S**) | Inbound: gateway signature verification + idempotent event ledger. Outbound: HMAC `t=…,v1=…` with timestamp for replay windows                                      | payments, webhook tests                                                              | Consumers must check the timestamp; documented in `docs/api.md`.                                                         |
| 10  | API key leakage (**I**)                                                       | Shown once, only hash stored, scoped, bearer-only (no cookie ambient authority), revocable, last-used tracked                                                       | platform tests                                                                       | A leaked key works until revoked.                                                                                        |
| 11  | Overselling / price tampering (**T**)                                         | Server computes all prices; stock reserved with row-level atomic updates; money as bigint; checkout idempotency keys                                                | commerce integration + concurrency tests                                             | None known. Totals are recomputed on the server at every step.                                                           |
| 12  | Malicious or buggy extension (**E/T/D**)                                      | Trusted in-process by design (ADR-0004); own DB role, read allowlist of Base tables, no core writes, CI import-boundary lint, `.client` tier fetch-only             | kernel/boundary tests                                                                | **An installed extension is trusted code.** Review before install. This is the largest accepted risk.                    |
| 13  | PII exposure in logs/reporting (**I**)                                        | Log redaction list, `sold_grafana` role read-only over PII-free views (column test), consent stored per order                                                       | log + reporting tests                                                                | Free-text fields (order notes) are not scanned.                                                                          |
| 14  | Secrets in repo/images (**I**)                                                | Env-only secrets, envelope encryption for stored secrets, `.env` ignored                                                                                            | none automated                                                                       | **No secret scanner in CI yet**; key rotation is manual (runbook).                                                       |
| 15  | Denial of service on a sale (**D**)                                           | Edge cache + ISR, shared cache, rate limits, queue back-pressure, degradation ladder (docs/scaling.md)                                                              | load tests (see capacity report)                                                     | Only measured on one machine; see report caveats.                                                                        |
| 16  | Dependency compromise (**T**)                                                 | Lockfile, `pnpm audit --audit-level high --prod` in CI (+SBOM job), minimal deps                                                                                    | `pnpm audit --prod` clean                                                            | Transitive dev-only advisories are not gated.                                                                            |
| 17  | Tampering with audit trail (**R**)                                            | Table has a BEFORE UPDATE/DELETE trigger that rejects changes (`audit_log_immutable`); writes share the change's transaction                                        | identity tests                                                                       | **No hash chain**: a DB superuser can drop the trigger and edit history. Ship logs to external WORM storage if required. |
| 18  | Account enumeration (**I**)                                                   | Uniform responses for login/reset/register-exists                                                                                                                   | identity tests                                                                       | Checkout email lookup is by design not exposed.                                                                          |

## Out of scope / assumed

Cloudflare/Azure configuration (8B) is Terraform-described but has **never been applied**; its controls (WAF, egress firewall,
private DB networking, Key Vault) are design intent until a real environment exists. Physical/host compromise and malicious DB
administrators are not modelled.
